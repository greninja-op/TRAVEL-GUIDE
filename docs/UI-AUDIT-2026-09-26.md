## 2. Token layer — what's real vs aspirational

`ui/theme/Tokens.kt` (18 lines) defines:
- **8 colors** — matches `design-reference/reference.html` `:root`. ✅ real
- **2 radii** — `CardRadius 10.dp`, `ButtonRadius 8.dp`. ✅ real
- **3 text styles** — Heading 24sp/600, Body 18sp/400, Chrome 14sp/500. ⚠️ partial:
  the reference's scale is 12/14/16/18/24/32/40; Tokens.kt has only 3 of 7 steps.

**Absent entirely from the token layer:**
- ❌ No spacing scale (reference says 4pt base: 4/8/12/16/24/32/48/64) — every screen
  hardcodes `16.dp` padding ad hoc.
- ❌ No elevation/depth scale — the reference allows exactly one shadow; not tokenized.
- ❌ No motion system — no durations, no easing curves, no `animate*AsState` anywhere.
- ❌ No alpha state layers (`--state-hover`, `--state-press`, `--primary-wash`,
  `--highlight-wash`, `--danger-wash`, `--scrim`) which the reference DOES define.

## 3. Confirmed defects (not opinions — verified)

### 3.1 Fonts are never loaded (design system is aspirational)
`DESIGN-TOKENS.md` and `design-reference/SKILL.md` both specify **Inter** (chrome) and
**Lora** (place stories). Verified:
- `find app/src/main -iname "*.ttf" -o -iname "*.otf"` → **no font files bundled**
- `grep -rn "FontFamily\|Inter\|Lora\|GoogleFont" app/src/main/kotlin/` → **zero matches**

**The app renders in the platform default (Roboto).** The typography half of the design
system is documentation-only. This is a primary "why does it look generic" cause.

### 3.2 The map's default style is a remote URL (breaks offline-first)
`ui/MapScreen.kt:18`:
```kotlin
private const val DEFAULT_STYLE = "https://demotiles.maplibre.org/style.json"
```
The app's core promise (SPEC §1.4) is a **full loop with zero network**. As written, a
first launch with no connectivity sets a remote style → the map renders blank. Needs a
**bundled local style JSON** as the default, with the remote URL as an explicit fallback.

### 3.3 The "now playing" sheet is not a sheet
`NowPlayingSheet.kt` is a `Card` inside the normal layout — no `ModalBottomSheet`, no
drag handle, no peek/expanded states, no scrim, and it cannot be dismissed by gesture.
Per the reference ("one bottom-sheet player") and every map app convention, this should be
a real M3 `BottomSheetScaffold` / `ModalBottomSheet` with anchored states.

### 3.4 Screens receive no data (engine not wired)
`MainActivity` passes `emptyList()` / `{}` to Nearby, Packs, History, and literal strings
to Routes. Until that's fixed the UI cannot show real content — **layout work on empty
screens cannot be visually validated.** Wiring and UI must land together.

### 3.5 Icons are not used at all
`grep` for icon usage: the nav bar passes `icon = {}` (empty). The reference mandates
Lucide (`ICONS-ASSETS/system-and-ui/lucide/icons`, 1,856 icons available, 24px box,
stroke 2, round caps, unfilled). **No icon is currently rendered anywhere.**

### 3.6 No states
No loading, empty, or error state exists anywhere except one History empty-text. DesignSoul
Step 6 requires all three. `PacksScreen` shows a progress bar but has no failure path.

## 4. Overlap/clipping risk (the owner's explicit concern)

Because screens are `Column` + `Text` with hardcoded `16.dp` padding and no `weight()`:
- `MapScreen`: `Modifier.fillMaxSize(0.7f)` for the map + a `TextButton` + conditional
  `Text` below — with long `seeingAnswer` text this **will** push past the viewport; there
  is no scroll and no max-lines.
- `PoiDetailScreen`: renders `card.history` (multi-paragraph) + all fun facts + see-list
  in a non-scrolling `Column` → **guaranteed overflow** on a real POI.
- `NowPlayingSheet`: `transcript` (a full story, 3+ sentences) in a fixed `Card` with no
  `maxLines`/scroll → overflow.
- No `LazyColumn` anywhere means long lists (24 POIs) render unbounded.

**These are structural, not cosmetic.** Any redesign must introduce scrolling containers,
`weight()`, and explicit `maxLines`/`overflow` policy — which is exactly what the owner asked to be verified.

## 5. What the redesign must therefore include

1. **Revise `reference.html` first** (rule 5 of `design-reference/SKILL.md`: "Need a genuinely
   new token? Add it to `reference.html` first, then use it"). New tokens needed: spacing scale,
   elevation scale, motion system (durations + curves beyond the current 100/150/200ms trio),
   full type scale, alpha state layers.
2. **Mirror** to `DESIGN-TOKENS.md` + `Tokens.kt` in the same turn.
3. **Bundle the fonts** (Inter + Lora) so typography is real.
4. **Build the component primitives once**: POI card, list row, player sheet, map pin, button —
   then compose screens from them (reference: "one implementation each").
5. **Real bottom sheet** for Now Playing with anchored states.
6. **Fix map defaults** — bundled style, designed pins, route line, camera animation.
7. **Wire data** so screens render real content (otherwise unverifiable).
8. **Overlap audit** — scrolling, `weight()`, `maxLines`, verified by inspection + APK build.

## 6. Verification limits (stated honestly, per DesignSoul)

- **Compose UI cannot be visually verified from here.** No browser tool exists for native
  Android rendering. `reference.html` CAN be opened in a browser, but the Compose app cannot.
- Available: **compile + `:app:assembleDebug`** (catches structural errors), and
  **`adb screencap`** on a connected device (real pixels — but the MIUI input-injection
  restriction blocks scripted navigation, so screens beyond the entry point need manual taps).
- **Anything not screenshotted is unverified.** This audit's static findings (§3.1–3.6, §4)
  ARE verified by grep/find and are reliable; claims about *how it looks* are not.

# 7. REMEDIATION — what was actually fixed (2026-09-26, Terminal 3)

Owner order: "triple quality" UI, smooth motion, premium map UI, no overlapping containers.
The reference.html lock was **waived by the owner for this phase** ("currently don't care about
that rule — that is for future implementation"), so tokens were expanded directly.

## 7.1 Foundation (verified: compiles, fonts confirmed inside the built APK)

| Defect | Status | Evidence |

## 7.2 Map hero (verified by grep on the actual source, not by the agent's report)

| Defect | Status | Evidence |
|---|---|---|
| §3.2 Remote default style breaks offline | **FIXED** | `MapScreen.kt:104` defaults to `MapStyle.LOCAL_STYLE_JSON` (bundled OSM raster + attribution); `REMOTE_FALLBACK_STYLE` demoted to an explicit opt-in. |

## 7.3 Shell

- **Nav bar rebuilt** — real icons + labels, animated selection pill, hairline border (no shadow).
- **Shell (defect 3.3)** — the Now Playing surface was a static `Card`; it is now a real player
  sheet body with a live playing indicator, a bounded scrollable story, an animated queue, and a
  48dp mute control.
- **Structural fix:** the mute button previously sat in a `Column` **above** the `NavHost`,
  stealing vertical space from every screen — a direct contributor to the overflow defects. It now
  lives in the player sheet, where the audio is.

## 7.4 Concurrent-agent collisions encountered (resolved)

Working three agents in parallel on one build caused real, fixable friction worth recording:
1. **Shared-symbol collision** — agents independently needed `GuideIcons`/`EmptyState` and
   `GuideColors`. Their files referenced helpers that did not exist yet, producing 65 errors that
   were *cascades*, not real breakage.
2. **A genuine name clash** — one agent defined a radio-button `RadioOff` into the shared icon file
   while an offline-signal icon already used that name. Resolved by renaming ours to `SignalOff`.
3. **Gradle daemon contention** — three concurrent builds produced
   `Daemon compilation failed: null` with **zero code errors**. Fixed by capping
   `org.gradle.workers.max=2` / `parallel=false` in `mobile/gradle.properties`.
4. **My own bug amplified it** — `cubicTo` is `curveTo` in Compose's `PathBuilder`; one wrong name
   in a new icon file accounted for the bulk of the cascade.

**Lesson for the next terminal:** when parallelising agents, define the shared interface
(primitives + icon set) *before* dispatching, and give agents non-overlapping *symbol* ownership,
not just non-overlapping files.

## 7.5 Still open (honest list)

- **No UI screen is wired to the engine** (§3.4) — Nearby/Routes/Packs/History still receive
  `emptyList()`/`{}`. Layout work on empty screens **cannot be visually validated** until this lands.
- **Visual verification is still impossible here.** Everything above is verified by compilation,
  grep and structural reasoning. **No visual claim is being made.**
- **Landscape / very short viewports** — the bottom region's bounded maxima (~440dp worst case)
  can approach the top cluster on a short viewport. Mitigated by making the sheet body scrollable
  so it degrades instead of colliding; not re-architected for landscape (the product is a
  walking-tour app used upright).
- Device QA still blocked on MIUI "USB debugging (Security settings)".

### Consistency fixes made after both agents finished
Two surfaces were missed (neither was in a nav tab, so neither agent owned them):
- **`SettingsScreen`** — non-scrolling column, battery cost a parenthetical rather than a
  disclosed figure. Rebuilt: scrolls, selecting a profile states its GPS cost *before* you tap
  (SPEC §1 battery honesty), background-location opt-in explains the real consequence.
- **`VoiceSettings`** — same pattern **plus a duplicated auto-play switch** that also existed in
  Settings. Two controls for one setting is two things that drift; the duplicate was removed.
- **`ConsentScreen`** — the two actions had equal visual weight, so "Not now" looked as encouraged
  as "Continue". Now ranked primary/secondary, with each product promise as a scannable row.
