Privacy Policy & Data Architecture

Effective Date: September 28, 2026 · Version 2.4.0 · Applicable to Travel Guide Mobile

1. Architectural Overview

Travel Guide is developed with an offline-first, local-processing architecture. The application is designed to function as an audio walking and driving guide without relying on remote user tracking or remote profiling servers.

All core functionalities—including GPS corridor proximity calculations, route rendering, place search, note taking, and voice narration synthesis—are executed entirely on the local device hardware.

2. Location Information

The application requires location access to determine proximity to historical monuments, cultural sites, and tourist destinations.

  • Foreground Processing: GPS coordinates are sampled while the application is active on screen to draw your current position and calculate distances to nearby landmarks.
  • Ephemeral Memory Only: Real-time coordinates are processed in volatile memory (RAM) and are not written to unencrypted log files or persistent location history databases.
  • No Cloud Uplink: Live GPS coordinates are never transmitted over the internet to analytics providers, advertisers, or remote backend infrastructure.

3. Google Maps Companion & Accessibility Service Disclosure

Travel Guide provides an optional Companion feature designed to work alongside Google Maps navigation. This feature utilizes Android's native AccessibilityService and/or NotificationListenerService APIs under the following constraints:

Accessibility Scope: The service is strictly scoped by the Android operating system to package com.google.android.apps.maps. It cannot observe, read, or interact with other applications.
  • Purpose: The service reads destination titles and navigation status updates directly from Google Maps when turn-by-turn navigation is started by the user.
  • Route Reactivity: When navigation is active, the app renders the matching road path and highlights corridor landmarks. When navigation is canceled or completed, navigation tracking terminates immediately.
  • Data Handled: Only public geographic destination strings (e.g., landmark names or street addresses) are extracted. The service does not read text input, passwords, search queries, payment data, or private account details.
  • Revocation: Accessibility and notification permissions can be revoked at any time via Android System Settings.

4. Data Storage & Cryptographic Protection

User-generated data—such as visited place records, custom trip notes, and preferences—is stored locally in an on-device SQLite database.

  • Hardware KeyStore: Sensitive credentials and local database encryption keys are managed through the Android KeyStore system, backed by hardware-isolated Secure Elements (StrongBox / TEE) where supported by the device.
  • Authenticated Encryption: Stored security tokens use AES-256-GCM authenticated encryption.

5. Audio Narration & Speech Synthesis

Place stories and walking instructions are converted from text to speech using the Android system's built-in Text-to-Speech (TTS) engine. Audio playback occurs locally; voice synthesis does not stream audio or text queries to external cloud speech APIs.

6. Third-Party Libraries & Telemetry

The application does not integrate third-party advertising frameworks, tracking pixels, or commercial telemetry SDKs. Map rendering is powered by open-source MapLibre Native using locally bundled style definitions and vector packs.

7. User Control & Data Sovereignty

You retain full authority over all data created during your travels:

  • Data Export: You may export your complete visit history, timestamps, and personal notes into portable Markdown format at any time.
  • Data Erasure: You can permanently wipe all local database tables and stored notes with a single tap in the Settings menu.
  • Operating System Permissions: All granted permissions (Location, Notifications, Accessibility) can be audited and toggled directly through Android Settings.

8. Contact & Policy Updates

If updates are made to this document, the revision date and version number will be updated accordingly. Inquiries regarding technical architecture or data practices may be directed to the repository maintainers.
